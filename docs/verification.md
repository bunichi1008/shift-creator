# 動作検証

2026-11-24 にローカルの合成データで検証した。ブラウザーは Chromium の PC 幅1280px、タブレット幅768px、スマホ幅390px を使用した。Cloud Run の実環境とスマートフォンの実機は未検証。

## 画面の設計

初回は対象期間とサンプル職員数、主操作の「シフト生成」、生成して確認・採用する手順を表示する。生成前は割当がないことを示し、手入力が必要な人は「手入力で始める」から勤務表を開ける。

継続利用時は勤務表を中心に置く。条件の追加、必要人数、勤務種別・休憩、職員・希望、共通ルール・最適化を上部から直接開ける。採用後の「シフトを再生成」「勤務案を検査」「CSV 出力」は勤務表と同じ画面に置く。診断は表の上に置き、該当ルールがあれば診断から編集できる。実行履歴は必要なときに開く。

## 機能シナリオ

| シナリオ | 確認結果 |
| --- | --- |
| 初期データで月間勤務表を生成・採用 | 24人・31日、必要人数を満たす勤務枠124/124、希望3/3、必須条件違反0 |
| 採用後に勤務を休みに変えて固定し再生成 | 固定を保持し、必須条件違反0の勤務表を生成 |
| 資格者の候補数を超える必要人数を指定 | 不足を診断し、実行不能な結果は採用できない |
| 06:00〜07:00の必要人数を設定 | 勤務の切れ目で不足を検出。診断から07:00〜08:00に編集して再生成すると採用できる |
| 同じ勤務の2人に30分休憩を設定 | 同時に休憩すると不足。12:00と12:30に交代すると在勤1人以上を維持し、採用後のセル固定でも開始時刻が残る |
| 取込エラーと復旧 | 下限が上限を超えるCSVは保存されず入力版が維持される。有効な希望CSVは保存され、サンプル復元で元の入力に戻る |
| 古い生成結果の採用とCSV | 古い入力版の結果は採用できない。出力したCSVには744セルと固定した休みが含まれる |

## ブラウザーのシナリオ

| 操作 | 確認結果 |
| --- | --- |
| 初回の生成、確認、採用 | サンプル職員と次の操作が見え、未生成時の勤務表は空状態になる。採用すると再生成とCSVが表示される |
| 上部から設定を開く | 必要人数、勤務種別・休憩、職員・希望、共通ルールの各入口が対応する設定を直接開く |
| スマホ幅で条件を追加し、不足を直す | 上部の設定を横スクロールなしで操作できる。診断は表の上にあり、該当条件を直接編集できる |
| 生成中と再読み込み後 | 生成中の再送ボタンは無効。未採用の直近結果は再読み込み後に開き直して採用できる |
| キーボードとキャンセル | Enter で条件を追加・編集でき、データ復元の取り消しと Escape でのダイアログ終了を確認 |
| OpenAI の設定あり・なし | 設定ありで日本語から2条件を提案し、確認後に一括登録。設定なしで手入力の条件追加・生成・診断が使用できる |

## 再実行

リポジトリのルートで次を実行する。Python の仮想環境は [README](../README.md) の手順で作る。

```sh
go -C web test -race ./...
PYTHONPATH=optimizer .venv/bin/python -m unittest discover -s optimizer/tests
scripts/smoke.sh
SMOKE_SOLVER=pulp scripts/smoke.sh
```

日本語のテスト用入力と期待結果は [評価データ](../contracts/llm-eval.json) に記録する。実APIを評価するときは、合成の12月データを使うOpenAI接続済みの検証用サーバーに対して実行する。

```sh
.venv/bin/python scripts/evaluate_llm.py --url http://localhost:8080 --allow-api-calls
```

2026-11-24 の `gpt-4o-mini` 実API評価では、構造化ルール13/13件、確認が必要な入力6/6件が期待と一致した。誤提案は0/19件で、応答時間の中央値は1.90秒だった。現在の評価データには、未対応の条件を明示できるかを確認するケースも含む。
