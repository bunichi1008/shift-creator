# Shift Creator

介護施設1拠点の月間勤務表を作成するツールです。Go が管理画面・API・ジョブ管理を担当し、Python が割当の検証とソルバー実行を担当します。日本語の入力は OpenAI API で条件案に変換し、管理者が確認してから登録します。

Python の既定のバックエンドは PuLP と HiGHS です。勤務条件から新しい割当を計算し、算出結果を独立に検証してから採用できる状態で返します。

## ローカルで試す

Go 1.24 以上と Python 3.12 が必要です。リポジトリのルートで仮想環境を作ります。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install './optimizer[test]'
```

ターミナル1で Python を起動します。

```sh
PYTHONPATH=optimizer .venv/bin/python \
  -m uvicorn shift_optimizer.api:create_app --factory --host 127.0.0.1 --port 8001
```

ターミナル2で Go を起動します。

```sh
cd web
go run .
```

[http://localhost:8080](http://localhost:8080) で「シフト生成」を押すと、24人分の合成データから勤務表をプレビューできます。「勤務案に採用」後、夜勤のセルを休みに変えて固定し、「シフトを再生成」を押すと、その固定を守った勤務表が出ます。資格者の最低人数を候補者数より多くすると、勤務表の上に不足箇所が表示されます。「該当条件を編集」から値を直し、再生成できます。

勤務条件は「条件を追加」から入力できます。勤務をまたいだ配置人数は「時間帯の最低人数」で指定します。例えば「毎日14時から17時まで最低6人」とすると、勤務と休憩の開始・終了で区切り、各区間で休憩中の人を除いた在勤者を合計します。資格を指定した場合は該当する職員だけを数えます。日をまたぐ時間帯では翌朝分も対象です。毎日の夜間ルールは初日の早朝にも適用し、前期間から続く勤務を履歴から数えます。「基本設定を編集」の「必要人数」では、勤務種別ごとの上下限を計算に使うかを選べます。

日本語の提案を使う場合は、Go の起動環境に `OPENAI_API_KEY` を設定してください。モデルは `OPENAI_MODEL` で指定でき、既定値は `gpt-4o-mini` です。提案を作るときに送るのは、発話、対象期間と職員・勤務・資格の名称と ID です。「12月12日にリーダーを常に2人」は当日の00時から24時までの在勤人数として提案し、「各勤務枠」と書いた場合は勤務別の条件として提案します。確認画面で確定すると、複数の条件を1つの版にまとめて登録します。合成データでの動作確認を想定しています。

Docker がある環境では `docker compose up --build` でも起動できます。ローカルの入力版と実行履歴は通常起動なら `.shift-creator/`、Compose なら `demo-data` ボリュームに保存します。

### データの入力と出力

- 初期画面に合成の職員24名、勤務種別、人員枠、希望を用意しています。「データ入出力」から職員・人員枠・希望の CSV をそれぞれ入れ替えられます。
- 画面上部の「条件を追加」「必要人数」「勤務種別・休憩」「職員・希望」「共通ルール・最適化」から各設定を直接開けます。必要人数は勤務種別ごとに全日に入力してから日別に調整できます。登録済みの資格者数や固定条件などは「勤務条件」の各行で編集できます。
- 「条件を追加」から、職員ごとの「休み希望（できれば）」「勤務不可（必ず休み）」「出勤可能日だけ指定」を登録できます。出勤可能日は毎週の曜日と個別の日付を併用でき、指定外の日は勤務不可です。夜勤も勤務開始日で判定します。「Bさんが出勤できるのは12月3日と12月7日だけ」のような日本語からも提案できます。
- 「勤務種別」では1〜12種類の勤務を設定できます。休憩は1勤務に複数設定でき、入力すると休憩を除いた実働時間が入ります。「開始時刻をずらせる」を選ぶと、最早・最遅の開始時刻と休憩の長さを設定できます。最早から5分刻みの候補と最遅の時刻から、PuLP が職員ごとに必要人数を満たす時刻を選びます。同じ職員の休憩は重複せず、ほかの目的が同じ案の間では、複数人の休憩が重なる時間を減らします。生成・採用した割当の休憩時刻は「日別の休憩予定」に開始順で表示します。勤務種別の削除時は、関連する勤務案・固定セル・個別条件などを保存前に確認します。前期間の記録は元の種別・時刻で保持します。
- 対象期間や前月の履歴を変更する場合は、設定 JSON を保存し、編集して再インポートしてください。職員 ID・日付などを変えた場合は、参照する条件・履歴も合わせて更新します。
- 「CSV 出力」から、編集中の勤務案を出力できます。ファイルの文字コードは UTF-8 です。

## PuLP モデルの構成

`optimizer/shift_optimizer/pulp_solver/` では、関連する制約をまとめ、割当変数と集計式を共用します。

| ファイル | 内容 |
| --- | --- |
| `model.py` | 割当変数 x[職員, 日, 勤務] と、職員・日・勤務枠ごとの集計を作る。勤務不可の割当は候補から外す |
| `coverage.py` | 勤務枠の人数の下限・上限、資格者の下限。診断時には下限の不足量も計算する |
| `breaks.py` | 職員ごとに調整する休憩の開始時刻と、同時休憩の重なりをモデル化する |
| `work_rules.py` | 1日1勤務、勤務・休みの固定、夜勤後の休息、勤務時間、連勤。前期間の履歴を参照する |
| `objectives.py` | 勤務希望、基準案からの変更セル、職員別の目標勤務時間・夜勤回数との絶対偏差 |
| `__init__.py` | HiGHS の実行、時間配分とステータス、実行不能時の診断 |

既定では、勤務希望の違反、基準案からの変更セル数、目標勤務時間と夜勤回数からの絶対偏差の順に最小化します。基準案がない場合は変更セル数を飛ばします。夜勤1回の偏差は既定で480分相当で、0にすると夜勤回数の偏差を評価から外します。先行段階で最適性を証明した値を固定し、全体の制限時間から残りを各段階に渡します。時間切れ時は、候補が得られていれば `feasible`、なければ `no_solution` です。境界とギャップは該当する探索段階について返します。

実行不能が証明された場合は、勤務不可と固定から分かる矛盾を表示します。診断用の計算では人員の最低要件に不足変数を加え、休息・固定・人員上限を維持したときに見直せる勤務枠を探します。診断結果は参照情報として表示されます。

`OPTIMIZER_SOLVER=pulp` が既定です。`demo` は固定サンプルでの画面確認用、`none` は未接続状態の確認用です。別のソルバーをつなぐ場合は Python の `solve(request: SolveRequest) -> SolveResult` を実装し、`OPTIMIZER_SOLVER=module:function` を指定します。

共通の JSON 契約は `contracts/solve-request.schema.json` と `contracts/solve-result.schema.json` です。`python -m shift_optimizer solve request.json` で単体実行できます。勤務時間は勤務開始日に計上し、前期間の勤務は休息・連勤の計算に使います。


## 検証

```sh
(cd web && go test -race ./...)
PYTHONPATH=optimizer .venv/bin/python -m unittest discover -s optimizer/tests -v
scripts/smoke.sh
SMOKE_SOLVER=pulp scripts/smoke.sh
```

OpenAI 連携はモックでテストできます。実際のモデルを比較する場合は、12月のサンプルを読み込んだ状態で `.venv/bin/python scripts/evaluate_llm.py --allow-api-calls` を実行します。評価用の入力についてルールの完全一致、曖昧な入力への確認、誤提案、応答時間を集計します。実行は API 利用量を消費します。

画面の操作と検証ケースは [動作検証](docs/verification.md) を参照してください。

## デプロイ構成

同じリポジトリから Go と Python のコンテナを個別に作ります。Cloud Run の Go が Firestore に現在の入力版と各ジョブの入力スナップショットを保存し、Cloud Tasks のコールバックを受けて、IAM 認証付きで非公開の Python サービスを呼びます。Python は入力を検証してソルバーを実行します。Go は実行権を版付きで管理し、二重配送や古い結果の採用を防ぎます。

[Cloud Run デプロイ手順](docs/cloud-run.md)
